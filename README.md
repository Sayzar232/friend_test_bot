Асинхронный Telegram-бот, с которым можно создать личный тест о себе и узнать, кто из друзей знает вас лучше всех. Бот работает через **webhook**, хранит данные в **PostgreSQL** и раз в неделю деликатно напоминает о себе.

👉 Попробовать: **[@Friendship_tests_bot](https://t.me/Friendship_tests_bot)**

---

## 📖 О проекте

Пользователь отвечает на 15 вопросов о себе, получает персональную deep-link ссылку и отправляет её друзьям. Друзья проходят тест (в личном чате или прямо в группе), бот сразу показывает правильные ответы, считает результат, ведёт таблицу лидеров и уведомляет владельца теста о каждом новом прохождении.

## ✨ Возможности

- 📝 **Создание и изменение своего теста** из 15 вопросов (`/edit_test`, кнопка «Создать мой тест»).
- 🔗 **Персональная ссылка** (`t.me/...?start=<payload>`) с кнопкой «Поделиться» — друг открывает её и сразу попадает в тест.
- ✅ **Мгновенная проверка ответов**: после каждого вопроса друг видит, угадал он или нет, и какой ответ был правильным.
- 🏆 **Результаты и лидерборд**: профиль со своими ответами, список тех, кто прошёл тест (с очками `X/15`), пройденные чужие тесты и «совместимость» с друзьями.
- 👥 **Тесты в групповых чатах**: команда `@username тест` запускает викторину в чате, в финале — «уровень дружбы» (Знакомый 😐 → Лучший друг 🫂).
- 🔔 **Уведомление владельцу**, когда кто-то прошёл (или завершил) его тест.
- 🚫 **Защита от накрутки**: один пользователь может пройти конкретный тест только один раз, свой собственный тест пройти нельзя.
- ⏰ **Еженедельные напоминания** (APScheduler + CronTrigger) с ротацией шаблонов текста, чтобы не спамить.
- 🛡 **Админ-панель** (`/admin`): статистика, рассылка с кнопкой-ссылкой, график роста пользователей (matplotlib) и список последних 100 пользователей.
- 📩 **Обратная связь**: `/feedback <сообщение>` пересылает текст администратору.
- ❤️ **Health-check** эндпоинты `/` и `/health` (ответ `OK`) — удобно для мониторинга и PaaS-проверок.

## 🧭 Как это работает

### 1. Создание собственного теста

1. `/start` → «📝 Создать мой тест» (или сразу `/edit_test`).
2. Бот задаёт 15 вопросов по одному — почти все с вариантами ответа на кнопках.
3. После последнего вопроса показывается предпросмотр теста и кнопки «Подтвердить» / «Отменить».
4. Ответы сохраняются в БД, а бот отдаёт персональную ссылку с кнопкой «Поделиться тестом».

### 2. Прохождение теста друга

1. Друг переходит по персональной ссылке (deep link) и нажимает «🚀 Пройти тест друга».
2. Отвечает на 15 вопросов «о тебе», видя после каждого ответа его правильность.
3. В конце получает результат `X/15`, разбор своих ответов и предложение создать собственный тест.
4. Владельцу теста приходит уведомление о новом прохождении.
5. Повторно пройти тот же тест нельзя — бот вежливо откажет.

### 3. Тест в групповом чате

1. В группе пользователь пишет `@username тест` (username владельца теста).
2. Бот проверяет, что пользователь есть в базе и у него создан тест, и предлагает начать.
3. Вопросы и результаты публикуются прямо в чате, а в финале бот показывает количество правильных ответов и уровень дружбы.

### 4. Профиль и результаты

`/profile` или кнопка «ℹ Результаты тестов»: имя, ID, сколько чужих тестов пройдено, сколько людей прошло ваш тест, ваша ссылка, ваши ответы, таблица лидеров вашего теста и совместимость с друзьями.

## 🗄 Схема базы данных

Таблицы создаются при старте (`Database._create_tables()`), а недостающие колонки добавляются миграциями (`database/migrations.py`).

| Таблица | Назначение | Ключевые поля |
| --- | --- | --- |
| `users` | все пользователи бота | `id` (PK), `full_name`, `username`, `ref_link`, `registration_date`, `other_test_passed`, `last_reminder_*` |
| `tests` | тест пользователя | `id` (PK → `users.id`), `num_users_passed`, `answers_updated_at` |
| `tests_answers` | правильные ответы теста | `test_id`, `question_index`, `answer` (PK: `test_id + question_index`) |
| `tests_results` | результаты прохождений | `id`, `test_id`, `taker_id`, `score`, `passed_at` (UNIQUE: `test_id + taker_id`) |

`ON DELETE CASCADE` настроен так, что удаление пользователя автоматически чистит его тест, ответы и результаты.

## 🚀 Быстрый старт

### 1. Требования

- Python 3.12 (минимум 3.10 — используется синтаксис `str | None`);
- PostgreSQL 13+ (локально, в Docker или облачный, например Neon/Render);
- публичный HTTPS-адрес для webhook (в разработке подойдёт `ngrok`).

### 2. Установка

```bash
git clone https://github.com/Sayzar232/friend_test_bot.git
cd friend_test_bot

python -m venv .venv
# Windows
.venv\Scripts\activate
# Linux / macOS
source .venv/bin/activate

pip install -r requirements.txt
```

Если PostgreSQL не установлен, его можно быстро поднять в Docker:

```bash
docker run -d --name friend-test-db \
  -e POSTGRES_PASSWORD=postgres \
  -e POSTGRES_DB=friend_test_bot \
  -p 5432:5432 postgres:16
```

### 3. Переменные окружения

Создайте файл `.env` в корне проекта (он уже добавлен в `.gitignore`):

```env
BOT_TOKEN=123456789:AA...ваш_токен_от_@BotFather
ADMIN_ID=123456789
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/friend_test_bot

WEBHOOK_URL=https://your-public-domain.example
WEBHOOK_PATH=/webhook
WEBHOOK_SECRET=случайная_строка_для_защиты_вебхука
PORT=8080

REMINDER_WEEKDAY=0
```

| Переменная | Обязательна | По умолчанию | Описание |
| --- | --- | --- | --- |
| `BOT_TOKEN` | ✅ да | — | токен бота от [@BotFather](https://t.me/BotFather) |
| `ADMIN_ID` | ✅ да | — | Telegram ID администратора: доступ к `/admin` и получатель `/feedback` |
| `DATABASE_URL` | ✅ да | — | DSN PostgreSQL, совместимый с `asyncpg` |
| `WEBHOOK_URL` | ✅ да | — | публичный HTTPS-адрес сервиса **без** пути (например, `https://bot.example.com`) |
| `WEBHOOK_PATH` | нет | `/webhook` | путь, на который Telegram шлёт обновления |
| `WEBHOOK_SECRET` | ✅ рекомендуется | — | `secret_token` для проверки подлинности запросов Telegram |
| `PORT` | нет | `10000` | порт, который слушает HTTP-сервер |
| `REMINDER_WEEKDAY` | нет | `0` (понедельник) | день недели для еженедельных напоминаний (`0`–`6`, где `0` — понедельник) |

> ⚠️ Время напоминаний (`REMINDER_HOUR = 18`, `REMINDER_MINUTE = 0`) и часовой пояс (`Europe/Moscow`) пока захардкожены в `settings.py` — из `.env` читается только день недели.

### 4. Локальный запуск

Бот работает **только через webhook**, поэтому Telegram должен «видеть» ваш компьютер. Проще всего пробросить порт через `ngrok`:

```bash
ngrok http 8080
# скопируйте выданный https-адрес в WEBHOOK_URL в .env
python main.py
```

При старте приложение:

1. создаёт пул соединений и таблицы, применяет миграции;
2. удаляет старый webhook и регистрирует новый (`WEBHOOK_URL + WEBHOOK_PATH`) с `secret_token`;
3. запускает планировщик еженедельных напоминаний (Europe/Moscow);
4. поднимает HTTP-сервер на `0.0.0.0:PORT` и отвечает `OK` на `/` и `/health`.

### 5. Деплой

Проект рассчитан на любой PaaS (Render, Railway, Heroku-совместимые хостинги), где есть `runtime.txt` и `PORT`:

- **Build command:** `pip install -r requirements.txt`
- **Start command:** `python main.py`
- **Переменные окружения:** из таблицы выше, где `WEBHOOK_URL` — это публичный адрес уже задеплоенного сервиса (например, `https://friend-test-bot.onrender.com`).
- Порт задавать вручную не нужно, если платформа сама прокидывает `PORT` (у Render по умолчанию `10000`).

> ℹ️ На бесплатных тарифах с «засыпанием» сервиса webhook перестаёт приниматься, пока контейнер спит. Для стабильной работы нужен всегда запущенный инстанс.

## 🛡 Админ-панель

Доступна только пользователю с ID из `ADMIN_ID` (команда `/admin`):

- 📊 **Статистика** — количество пользователей, общее число прохождений, число созданных тестов, средний результат, самые частые ответы по вопросам, топ-5 тестов и доля пользователей, прошедших хотя бы один тест.
- 📢 **Рассылка** — бот просит текст сообщения, затем URL и текст кнопки (или `no`, если кнопка не нужна), и отправляет сообщение всем пользователям с отчётом о количестве доставленных.
- 📈 **Рост пользователей** — график кумулятивного роста, который строится на лету (`matplotlib`, `Agg`) и отправляется картинкой.
- 👥 **Последние 100 пользователей** — список свежих регистраций по `registration_date`.

## 🔔 Еженедельные напоминания

Планировщик (`APScheduler`, `CronTrigger`) запускается вместе с приложением и раз в неделю проходит по пользователям:

- **Нет теста** → шаблон из группы `create_test` с кнопкой «Создать тест».
- **Тест есть, но давно не было активности** → шаблон из группы `share_test` с кнопкой «Поделиться».
- Шаблон выбирается случайно, но никогда не повторяет предыдущий для того же пользователя, а повторное напоминание возможно не чаще, чем раз в 7 дней (`last_reminder_kind`, `last_reminder_template`, `last_reminder_sent_at` в таблице `users`).
- Ошибки отправки (`TelegramForbiddenError`, `TelegramBadRequest`) логируются и не прерывают рассылку.

## 🧩 Архитектура

- **Точка входа** — `main.py`: `Dispatcher` + порядок роутеров `group → user → callbacks → states → admin → answers_callbacks`, `SimpleRequestHandler` для webhook, `setup_application` для aiohttp.
- **Конфигурация** — `settings.py` читает `.env` через `python-dotenv` и раздаёт константы всему приложению (остальные модули не работают с `os.environ` напрямую).
- **База данных** — класс `Database` в `database/database.py` владеет пулом `asyncpg` и всеми SQL-запросами; остальной код использует готовый синглтон `db` из `database/__init__.py`. Миграции идемпотентны (`ADD COLUMN IF NOT EXISTS`), поэтому запускать их безопасно при каждом старте.
- **Хендлеры** — тонкие: собирают клавиатуры и текст, а данные берут только через `db`; логика ответов/подсчёта очков вынесена в чистые функции (`calculate_right_answers`, `build_test_str`, `is_correct_answer` и т. п.), которые легко тестировать.
- **FSM** — состояния описаны в `utils/states.py` (`Form`): создание теста, ответы друга, текстовые ответы, шаги рассылки.
- **Клавиатуры и данные** — `utils/keyboards.py` генерирует инлайн-клавиатуры из словарей `utils/answers.py`, а вопросы лежат отдельно в `utils/questions.py` (набор «для себя» и набор «для друга»).
- **Deep links** — `aiogram.utils.deep_linking.create_start_link(..., encode=True)`, на входе payload декодируется и превращается в `test_id` друга.

## ⚠️ Известные ограничения

- Состояния FSM хранятся в памяти процесса (`MemoryStorage`): незавершённая анкета теряется при перезапуске бота, а несколько инстансов не делят состояния. Для продакшена с масштабированием нужен `RedisStorage`.
- Время и часовой пояс напоминаний заданы в коде (`settings.py`), а не через переменные окружения.
- Все 15 вопросов отвечаются кнопками; обработчик текстовых ответов и валидаторы (`validate_height`, `validate_birth_year` в `handlers/message_handlers.py`) остались от прежнего набора вопросов.
- Групповой сценарий работает только для пользователей с заполненным `username`, которые уже есть в базе бота.
- Автотестов в репозитории пока нет, `test.py` — локальный черновик подключения к БД (в `.gitignore`).

## 🔐 Безопасность

- `.env` добавлен в `.gitignore` — не коммитьте токен бота, DSN базы и `WEBHOOK_SECRET`.
- Всегда указывайте `WEBHOOK_SECRET`: он передаётся в `set_webhook(secret_token=...)` и защищает endpoint от посторонних запросов.
- Если токен бота всё же попал в публичный доступ — перевыпустите его в [@BotFather](https://t.me/BotFather) командой `/revoke`; при утечке `DATABASE_URL` смените пароль пользователя БД.
- Доступ к админ-функциям ограничен сравнением `from_user.id` с `ADMIN_ID`.
